# Runbook: bot account setup

The bot is a GitHub machine user named `iztac-bot`. It files issues, applies labels, comments,
requests reviews, and reviews pull requests on repositories you own. It cannot push code and it
cannot merge. Every step below is performed by you, by hand, once. Nothing here is automated.

The bot is added only to repositories under your own account. It is never invited to any
organization or to any repository you do not own.

## 1. Mailbox

1. Create the mailbox `iztac-bot@agentmail.to`.
2. Store the mailbox credentials in 1Password (item name in section 6).
3. Confirm you can receive mail there before continuing. GitHub sends the verification link and,
   later, any recovery mail to this address.

## 2. GitHub account

1. Sign out of your own GitHub session, or use a private browser window.
2. Create the account at https://github.com/signup with:
   - Username: `iztac-bot`
   - Email: `iztac-bot@agentmail.to`
   - Password: generated by 1Password, 32 characters or longer.
3. Verify the email address from the mailbox.
4. Profile: set the display name to `iztac-bot`. Leave the bio empty. Do not add a company,
   location, or website.

## 3. Two-factor authentication

1. Settings, Password and authentication, Enable two-factor authentication.
2. Choose the authenticator app method and scan the QR code into the 1Password item, so the
   TOTP code lives beside the password.
3. Download the recovery codes and attach the file to the same 1Password item.
4. Do not register your own phone number or passkey on this account.

## 4. Email privacy and notifications

1. Settings, Emails: turn on **Keep my email addresses private** and **Block command line
   pushes that expose my email**.
2. Record the noreply address shown on that page. It has the form
   `<id>+iztac-bot@users.noreply.github.com`. This is the address used in the co-author trailer:

   ```
   Co-authored-by: iztac-bot <<id>+iztac-bot@users.noreply.github.com>
   ```

3. Settings, Notifications: turn off every email notification for this account. Under
   **Default notifications email**, leave the address, but disable email under Participating,
   Watching, Dependabot alerts, Actions, and every other category. Under **Customize email
   updates**, uncheck every box. The mailbox exists for account verification and recovery, not
   for traffic.
4. Settings, Emails: uncheck **Receive all emails, except those I unsubscribe from** if it is
   shown, and unsubscribe from marketing.

## 5. Fine-grained personal access token

One token per repository. Do not create a token that spans all repositories.

1. Settings, Developer settings, Personal access tokens, Fine-grained tokens, Generate new token.
2. Token name: `dev-platform` (use the repository name for each later token).
3. Resource owner: `iztac-bot`. The repository must already have the bot as a collaborator
   (section 7) before it appears in the list.
4. Repository access: **Only select repositories**, choose the one repository.
5. Permissions (repository):
   - Issues: **Read and write**
   - Pull requests: **Read and write**
   - Metadata: **Read-only** (set automatically)
   - Contents: **Read-only**
   - Everything else: **No access**
6. Expiration: 90 days. Note the expiry date in the 1Password item. Rotation is a calendar
   reminder, not an automation.
7. Copy the token once into 1Password. It is never written to a file, a shell history, or a
   repository.

The token cannot write contents, so even a token leak cannot push code.

## 6. 1Password

Create one item in the Private vault:

- Item name: `GitHub iztac-bot`
- Username: `iztac-bot`
- Password: the account password
- One-time password: the TOTP secret from section 3
- Attachment: the recovery codes file
- Field `noreply`: the address from section 4
- Field `mailbox`: `iztac-bot@agentmail.to`, with its own password in a linked item named
  `Mailbox iztac-bot@agentmail.to`
- Field `token dev-platform`: the fine-grained token, with a note holding its expiry date.
  Add one field per repository token.

Tools that act as the bot read the token from 1Password at run time. Your own `gh` login is
never present in a shell that acts as the bot.

## 7. Triage role

For each repository the bot works in:

1. Repository, Settings, Collaborators, Add people, `iztac-bot`.
2. Role: **Triage**. Not Write, not Maintain.
3. Accept the invitation from the bot account (or from the mailbox).

Triage lets the bot manage issues, labels, milestones, and pull request metadata, and leave
reviews. It cannot push, cannot merge, and its reviews do not satisfy a required approval.

## 8. Verification

Run these from a shell with only the bot token, on a repository that has the rulesets applied:

1. Clone the repository and try to push a branch:

   ```
   git push origin HEAD:refs/heads/probe
   ```

   Expected: refused. The token has no contents write permission.

2. From your own account, open a test pull request. From the bot, comment on it and leave an
   approving review. Expected: the review posts, the pull request still cannot merge, and the
   pull request page shows the approval as not counting toward the required review.

3. Delete the test pull request's branch from your own account. Close the pull request.

When both checks behave as expected, this runbook is complete. Record the completion date in
the 1Password item's notes.
